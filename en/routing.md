# Routing

Routes map a URI and HTTP method to an action. They are registered with the `Luany\Core\Routing\Route` facade in the files under `routes/`.

## Route files

The Kernel loads `routes/http.php` first, then every other `*.php` file in `routes/` in alphabetical order. Split routes by area whenever a file grows:

```
routes/
  http.php      ← loaded first
  admin.php
  api.php
  posts.php     ← generated by: luany make:feature Post
```

Run `luany route:list` to see every registered route.

## Basic routes

```php
use App\Controllers\PostController;
use Luany\Core\Http\Request;
use Luany\Core\Routing\Route;

Route::get('/', fn () => 'Hello, Luany!');

Route::get('/posts', [PostController::class, 'index']);
Route::post('/posts', [PostController::class, 'store']);
Route::put('/posts/{id}', [PostController::class, 'update']);
Route::patch('/posts/{id}', [PostController::class, 'update']);
Route::delete('/posts/{id}', [PostController::class, 'destroy']);

Route::any('/ping', fn () => 'pong');   // every method
```

An action is a closure or a `[Controller::class, 'method']` pair. See [Controllers](controllers.md).

`HEAD` requests are answered by the matching `GET` route, without a body. Routes are matched in registration order; the first match wins.

URIs may contain dots, as in `Route::get('/sitemap.xml', ...)` or `/feed.json`. They match the same way under `luany serve` / `luany dev` as behind Apache or Nginx.

### Return values

| Action returns | Response |
| --- | --- |
| `Response` | Sent as is |
| `string` | HTML body, status 200 |
| `array` or object | JSON (`Response::json()`) |
| `null` | Empty body, status 200 |

## Route parameters

Wrap a segment in braces to capture it. A parameter matches one path segment (anything except `/`):

```php
Route::get('/posts/{id}', function (Request $request, string $id) {
    return "Post {$id}";
});

Route::get('/users/{user}/posts/{post}', [UserPostController::class, 'show']);
```

Parameters are passed to the action **by name**, so their order in the signature does not matter. Parameter names must start with a letter or underscore. Optional parameters and regular-expression constraints are not supported — validate the value in the action and `abort(404)` when it is invalid.

### Numeric parameters

A parameter whose action argument is declared `int` or `float` is converted to that type. A segment that is not a valid number answers **404**, before route middleware runs:

```php
Route::get('/posts/{id}', fn (int $id) => "Post #{$id}");   // /posts/7 → 7, /posts/abc → 404
```

See [Controllers](controllers.md#scalar-types) for the exact rules.

### Form method spoofing

HTML forms can only send `GET` and `POST`. Add a `_method` field to a `POST` form to reach a `PUT`, `PATCH` or `DELETE` route:

```lte
<form method="POST" action="/posts/{{ $post->id }}">
    @csrf
    @method('DELETE')
    <button>Delete</button>
</form>
```

## Named routes

Name a route with `name()` (or the third argument) and generate its URL with the `route()` helper:

```php
Route::get('/posts/{id}', [PostController::class, 'show'])->name('posts.show');
Route::get('/about', [PageController::class, 'about'], 'about');
```

```php
route('posts.show', ['id' => 5]);            // http://localhost:8000/posts/5
route('posts.show', ['id' => 5, 'tab' => 'comments']);
                                             // http://localhost:8000/posts/5?tab=comments
```

Values are URL-encoded and prefixed with `APP_URL`; parameters that are not in the pattern become the query string. A missing parameter throws an `InvalidArgumentException`; an unknown name throws a `RuntimeException`.

## Route groups

Groups share a URI prefix and/or middleware:

```php
use App\Http\Middleware\AuthMiddleware;

Route::prefix('admin')->middleware(AuthMiddleware::class)->group(function () {
    Route::get('/dashboard', [AdminController::class, 'dashboard']);   // /admin/dashboard
    Route::get('/users', [AdminController::class, 'users']);           // /admin/users
});

Route::middleware([AuthMiddleware::class, AuditMiddleware::class])->group(function () {
    Route::get('/account', [AccountController::class, 'show']);
});

// Array form
Route::group(['prefix' => '/api', 'middleware' => [ApiMiddleware::class]], function () {
    Route::get('/status', fn () => ['ok' => true]);
});
```

Groups can be nested: prefixes are joined and middleware lists are merged, outermost first.

> **Note** Calling `middleware()` twice on the same group replaces the first list. Pass all of a group's middleware in one array.

Group options cover `prefix` and `middleware` only — route names are not prefixed, so name each route in full.

## Resource routes

`Route::resource()` registers the seven conventional CRUD routes for a controller:

```php
Route::resource('posts', PostController::class);
```

| Method | URI | Action | Name |
| --- | --- | --- | --- |
| GET | `/posts` | `index` | `posts.index` |
| GET | `/posts/create` | `create` | `posts.create` |
| POST | `/posts` | `store` | `posts.store` |
| GET | `/posts/{id}` | `show` | `posts.show` |
| GET | `/posts/{id}/edit` | `edit` | `posts.edit` |
| PUT | `/posts/{id}` | `update` | `posts.update` |
| PATCH | `/posts/{id}` | `update` | — |
| DELETE | `/posts/{id}` | `destroy` | `posts.destroy` |

Limit the actions with `only` or `except`; `apiResource()` leaves out the two form routes (`create`, `edit`):

```php
Route::resource('photos', PhotoController::class, ['only' => ['index', 'show']]);
Route::resource('tags', TagController::class, ['except' => ['destroy']]);
Route::apiResource('comments', CommentController::class);
```

Resource routes always use `{id}` as the parameter name.

## View routes

When a route only renders a template, skip the controller:

```php
Route::view('/about', 'pages.about');
Route::view('/terms', 'pages.legal', ['title' => 'Terms of Service'], 'terms');
```

The view receives exactly the data you pass. Request input is never merged into it.

## Route model binding

Model binding replaces a raw parameter value with an object before the action runs.

`Route::model()` resolves a parameter with the model's `find()` method:

```php
use App\Models\Post;

Route::model('post', Post::class);

Route::get('/posts/{post}', [PostController::class, 'show']);
```

```php
public function show(Post $post): string
{
    return view('pages.posts.show', compact('post'));
}
```

`Route::bind()` registers any resolver — for example, a lookup by slug:

```php
Route::bind('post', fn (string $slug) => Post::firstWhere('slug = ?', [$slug]));
```

A binding applies to **every** route that has a parameter with that name. When the resolver returns `null`:

| Action parameter | Result |
| --- | --- |
| `Post $post` (non-nullable) | 404 Not Found |
| `?Post $post` | The action receives `null` |

## Errors: 404 and 405

A URI that matches no route produces a **404**. A URI that matches a route registered for a different method produces a **405 Method Not Allowed** with an `Allow` header listing the accepted methods. Both are rendered by the [error handler](errors.md).

## Route caching

The router can export its route table to a PHP file and load it back without executing the route files:

```php
$path = base_path('storage/cache/routes.php');

Route::cache($path);        // write the current table (atomic write)
Route::loadCache($path);    // true when the file was loaded
Route::clearCache($path);   // delete the file
```

A route table is cacheable only when every action and middleware survives `var_export()`:

| Cacheable | Not cacheable |
| --- | --- |
| `[Controller::class, 'method']` actions | Closure actions |
| `Route::view()` routes | Middleware given as objects without `__set_state()` |
| Middleware given as class names | `Route::bind()` resolvers (closures) |
| `Route::model()` bindings | |

`Route::cache()` throws a `RuntimeException` listing every offending route instead of silently dropping it.

### Using the cache in the Kernel

When `storage/cache/routes.php` exists, the HTTP Kernel loads the routes from it and **does not run the route files**. Generate it after loading the route files — for example with a small script run on deploy:

```php
<?php
// bin/route-cache.php
use Luany\Core\Routing\Route;
use Luany\Framework\Http\Kernel;

$app    = require __DIR__ . '/../bootstrap/app.php';
$kernel = $app->make(Kernel::class);
$path   = $kernel->routeCachePath();       // base_path('storage/cache/routes.php')

Route::clearCache($path);                  // so boot() reads routes/*.php, not an old cache
$kernel->boot();
Route::cache($path);

echo "Routes cached: {$path}\n";
```

```bash
php bin/route-cache.php
```

- A cache file is used until it is deleted: regenerate it on every deploy and run `Route::clearCache()` (or delete the file) whenever routes change. Do not create it in development.
- `Route::bind()` resolvers are closures and are not cached. When you use the cache, register them in a service provider's `boot()` method instead of a route file.
- To change the location, override `protected string $routeCacheFile` in `App\Http\Kernel` (relative to the project root); set it to `''` to disable the cache.

The CLI has no `route:cache` command. See [Deployment](deployment.md#routes).
